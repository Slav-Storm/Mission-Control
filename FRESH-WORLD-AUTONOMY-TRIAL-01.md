# Fresh-world autonomy trial 01

5 October 2026 — **FAILED EARLY: MISSING CLEAN-START CAPABILITY**

The accepted development-colony migration was followed by its published architecture report, then this separate disposable trial. The trial did **not** pass autonomous progression. It stopped at commissioning/strategic-start boundaries before opening a physical operations window. It was not extended to five Minecraft days simply to accumulate idle time.

The development colony remains preserved. The final production/YouTube run has **not** started.

## What was actually tested

A new Survival world was created in the installed Monifactory instance, using its default generation and Peaceful setting. It received a new run identity, publicly identified here as `trial-01 / 0331107a`. No development world was cloned, reset or repurposed. No seed or hidden terrain was inspected.

The existing clean-package initializer produced an empty namespace. Before enrollment, verified counts were zero for cells, deposits, containers, slots, reservations, requests, jobs, events, history, claims and entities. Static knowledge remained available: 911 quests, 18 bounded production recipes, 8 capability definitions and 21 technology records. These are knowledge records, not physical capabilities. The initializer did not carry over the development run's effective-recipe runtime approval, equipment availability or dispatch approvals.

The computer and all ten turtles supplied authenticated, run-bound telemetry. The player remained at the recorded anchor; no movement input was sent.

## Exact result and causal limits

**1. Fresh commissioning is missing.** The existing initializer deliberately creates an offline, empty, held namespace. The accepted operational activation machinery is a migration/handover path, relying on verified prior state and a committed epoch. A fresh colony needs its own explicit commissioning path with physical enrollment, new-run recipe binding, capacity verification and a finite operating permit. Copying development approvals or inventing a legacy snapshot would defeat run isolation. That was not done.

The trial therefore used the existing observation-only runtime and authenticated spool transport. This is real physical telemetry, but is **not** evidence that the operational robot executor or autonomous standing policies ran in the fresh world.

**2. Broad progression intent has no implemented Director operation.** The requested broad intent, “Begin legitimate Monifactory progression using the autonomous colony architecture,” was recorded as one persistent `OBJECTIVE`, with the explicit trial vocabulary `BEGIN_MONIFACTORY_PROGRESSION`. The actual Director returned `BLOCKED / OBJECTIVE_UNSUPPORTED`, with no child requests or jobs. That vocabulary is not a documented executable operation; this test exposes the absence of a broad starting-strategy adapter. It does not imply that existing supported production, survey or stock-maintenance objective types failed.

No individual turtle was manually assigned a progression task to conceal that gap. No new general planner was built during the observation trial.

**3. Fresh-run viewer initialization is missing.** The existing PC projection returned `PC_VIEW_REQUIRES_COMMITTED_EPOCH`. Source inspection also identifies a later requirement for a legacy import. Consequently a clean epoch-zero colony cannot currently appear in the existing live viewer without additional initialization support. The development viewer/timeline acceptance remains valid, but it must not be generalized into a claim that fresh-run rendering passed.

**4. A full clean-run timeline was not demonstrated.** The new ledger retained its own bootstrap-era observation events with native Minecraft-day samples. No development history was imported. The first physical day sample was Day 1; no Day 0 reconstruction was fabricated. This preserves the trial's recorded history, but does not satisfy the intended complete live timeline from world creation.

## Preservation and engineering interventions

Interventions were limited to new-world creation, the explicitly allowed exact bootstrap, portable software installation, observation collection, submitting the single broad intent, and normal saving/shutdown. These are setup/engineering actions and are not counted as autonomous gameplay.

No uncertain physical action was replayed. All ten bootstrap fuel receipts, authenticated observations, the blocked request, local database, initialization evidence, bootstrap program and closed trial-world archive are preserved locally. The development world's 653 archived files were compared as opaque bytes against its pre-trial backup and matched. Its PC configuration also remained byte-identical. This comparison did not decode terrain. Protected development quest resources were not touched.

Both worlds were saved normally. Minecraft was closed. The development PC service remains stopped with its last accepted authority held; the finite trial observer exited. No final clean/filmed world was started. The trial remains preserved for diagnosis, not erased and rerun until it appears successful.

## Recommended next engineering stage

1. Add a first-class **fresh-run commissioning transaction** using the existing authority model, with real bootstrap reconciliation, unique computer allocation, current recipe/runtime binding and a finite permit. It must never require fabricated legacy data.
2. Make the existing viewer accept an explicitly empty native PC run and display observation-only commissioning state. Preserve the same read-only boundaries and run-isolated history.
3. Add a bounded **opening strategy** that chooses supported objectives from observed surroundings, starting equipment, fuel and recipe/capability constraints. Missing storage, tools and routes must remain real dependencies, not supplied test conveniences.
4. Test those additions independently, then run a separately identified second disposable trial with the same resource allowance. Do not silently replace Trial 01's failure evidence.

Another fresh trial is warranted **after** those specific gaps are repaired. The architecture is **not ready for the eventual filmed clean run** based on Trial 01. The accepted migration proves operation of the reconciled development colony; it does not yet prove that the system can commission and direct a colony from nothing.

Raw telemetry, coordinates, databases, credentials, world archives and implementation source remain local. This report is a sanitized engineering summary.
